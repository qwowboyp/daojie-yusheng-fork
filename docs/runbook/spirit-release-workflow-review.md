- 兩份 `aa73d590cf6d` 前端候選已完成驗證，卻分別因 Nginx 行尾契約、同版本不可變圖包衝突而無法發布。收據的驗證時間為 374.090 秒與 364.889 秒，合計 **738.979 秒（約 12 分 19 秒）**。這是已發生的驗證耗時，不是新工具的實測節省率。
- 該候選完整發布門禁曾通過，耗時 1,382.399 秒；後續來源修正必須重新綁定最終 SHA，不能把舊候選收據挪給新版本。
- QA 初始化未一次涵蓋 runner／shadow 分離、環境別名、建表順序與 GM 就緒；新 stage 又漏做 server 編譯，導致可在開跑前發現的錯誤延後出現。
- server 的 `build` 實際指向 `pnpm verify`。準備單一 smoke 時誤用此指令，重複啟動整套測試。
- 手動 ledger 認領測試同時啟動背景 consumer，偶發搶走測試資料。已在手動斷言前等待背景任務停止，保留原有認領、重試、分組與 fencing 斷言。
- GM 測試每次將地圖速度加 2 並持久化，卻未在結束時還原。重複執行累積到 9 後，下一次期待 11，超過正式上限 10，造成確定性的讀回逾時。修正必須同時涵蓋合法取值與狀態還原，不能靠重新建立資料庫掩蓋污染。
- 舊退出碼檔、不同 helper 的輸出格式，以及代理在程序未結束時回報收尾，增加查詢與交接。不能把 log 的 `ok` 當成程序退出碼。

## 已落實的改進

新增 [前端發布預檢](../../scripts/client-release/preflight.py)，在昂貴建置前用一次 SSH 唯讀資料取得核對 Nginx 範本與不可變圖包，僅輸出精簡 JSON。涵蓋行尾差異、同版本改圖、刪除檔案、版本漂移與新版本；保留所有正式發布守門。

工具的 6 項測試與 `pnpm verify:workflow` 均通過；此改善隨發布後的流程文件提交，不改已上線的遊戲版本。沒有宣稱未量測的加速比例。

本次真實唯讀預檢核對兩個 Nginx 範本及 220 個圖包檔案，確認第 12 版快照尚未存在。工具的來源與線上比對不修改 receipt、快照或容器。

GM 修正另以 QA 的 `public:yunlai_town` checkpoint 實測上限：先讀取實際 JSON 結構，只更新頂層 `tickSpeed`／`paused` 並確認恰好一列，再連跑原 smoke 兩輪。兩輪均為初值 10、測試值 9、結束讀回 10／false，退出碼皆為 0。證據在 `.runtime/releases/spirit-beast-6c58de7f5a80/gm-max10-evidence.json`；沒有修改正式服務、測試逾時或斷言。

## 後續固定執行順序

1. 一次確認最終提交、線上基底 receipt、受保護容器、發布工具入口與本次路徑；先跑上述預檢。讀取腳本對應命令後再執行，不由 `build` 名稱推測其行為。
2. 沿用任務隔離 QA；runner 與 shadow 必須使用不同資料庫，四個 DB 別名要一致指向各自目標。一次確認 test runtime、CORS、GM、Node WebSocket 選項、必要 schema 和 shadow 的 JSON 健康／GM 回應。健康檢查使用 server 連接埠，不能把前端 SPA 的 HTTP 200 當成健康。
3. 單純補編譯使用 `pnpm --filter @mud/server exec tsc -p tsconfig.json`。先確認目標測試執行檔存在；已知失敗用對應案例確認修正，再進正式門禁。
4. 每個 runner 使用獨立 stage／log／exit／metadata；啟動時移除該輪舊狀態，完成後才寫退出碼。依輸入 SHA、命令、環境與實際退出碼辨識證據。日誌完整落盤，只回傳階段、耗時、退出碼和失敗摘要。
5. 對固定 SHA 執行一次完整四門禁。成功後前端 `prepare` 與 server-only 發布準備可並行；server 健康且 revision 正確後才切前端。`prepare` 已含 client 驗證，不在前後自行再跑一次。
6. 代理僅承接有界、可獨立交付的責任。交接列明既有環境、檔案所有權與真正完成條件；程序仍在執行時回報進度和 session ID，不能將其標記完成。主程式輸出不等於 finally 還原證據，應讀回真正資料；資料庫 fixture 先核對實際 JSON 結構，不能從包裝型別推測落盤欄位。等待以 30–60 秒為單位，同一結果不由多人重查。
7. 前後端上線並完成實際 HTTP／hash／容器核對後，才清除 QA 和臨時 worktree；保留回復包及證據，不提早拆除尚可能重用的驗證環境。

原始兩份收據位於 `.runtime/releases/spirit-beast-aa73d590cf6d/client/`、`client-crlf/`；時間證據在同層 `full-timing.json`。會話稽核在 `.runtime/reports/spirit-workflow-audit/`，屬期間快照且涵蓋其他任務，不能直接當作本次最終 token 成本；未宣稱固定 token 或工具呼叫節省百分比。
